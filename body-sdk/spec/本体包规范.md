# 本体包规范(公开版)——灵智系统本体包对接规格

> 本文件 = 厂商交付规格的公开版:包结构/版本门/**传输制式与微码**/策略行/快脑行/校验清单/签名口径。
> 完整字段级规范(全部段逐字段+拒收对照全表)随合作交付;与引擎实现不一致处以引擎为准。

## 0. 包结构与交付流程

```
<package_name>/
├── body-package.toml        # 清单 + 签名 + 全部配置段
├── policies/                # 策略 ONNX 权重(路径相对包根)
├── fastbrains/              # 快脑 ONNX 权重(声明了 fastbrains 段才需)
└── microcode/               # 传输/采集/输出微码 .so(微码制式才需;build.sh 编译)
```

交付流程(顺序即流程):

```
1. 填 body-package.toml(本规范逐段)
2. 预检:python tools/validate.py <目录> --dev     ← 校验清单,照单修
3. 放入权重(policies/*.onnx——训练 = rl-training 平台,契约对齐)
4. 签名:python tools/sign_package.py <目录> <私钥PEM>   (--generate 先生成密钥对)
5. 严格校验:python tools/validate.py <目录>       ← 全绿 = 交付
6. 灵智系统侧最终验收:tri 在环套件全绿 → 认证上线
```

## 0.5 传输制式与微码(厂商低层协议适配——引擎零改动)

**接新厂商本体 = 两段式,引擎不动:**

| 段 | 形态 | 内容 |
|---|---|---|
| ① 声明段(填) | body-package.toml `[protocol]` | 传输制式(dds)× 关节映射 × topic/type_name/QoS——**填表** |
| ② 微码(写一次) | `microcode/*.so`(build.sh 编译) | **厂商低层载荷编码器**:按该厂商公开协议把引擎的关节目标流编码为其低层指令(含 CRC 等),经 ABI 接口挂入引擎 |

规则:

- 引擎机制本体无关——对厂商协议**零感知**;厂商差异全部收在微码里(引擎经 ABI 调用,ABI 版本门 `core.abi_version` 保证微码模板与引擎匹配)。
- 微码 = **每厂商一次性**工程(照其公开 SDK/IDL 写);写完进兼容列表,同型本体永久复用,引擎永不因新本体而改。
- 例:宇树 G1 = `rt/lowcmd` 的 LowCmd IDL 打包 + CRC(unitree_sdk2 开源协议)——样例包 `examples/unitree-g1` 头部"已知边界"即此微码的待办标注。

## 1. 版本门(manifest 校验,最先执行)

| 字段 | 约束 | 失败行为 |
|---|---|---|
| core.word_schema_version | ∈ 引擎支持集(当前 [1]) | 拒收 |
| core.abi_version | == 引擎 ABI 版本(微码模板匹配门) | 拒收 |
| core.runtime_min | 引擎版本 ≥ 此值 | 运行时拒绝 |

## 2. 必填/可缺省段

| 段 | 必填 | 内容 |
|---|---|---|
| core + signature | ✅ | 清单版本与签名 |
| protocol | ✅ | 传输制式 × 关节映射(joint_mapping.ordered = 关节序权威) |
| profile | ✅ | 关节几何/限位/中立位锚 |
| calibration | ✅ | 标定中立位(每关节——**必须在软限位内**,margin 0.05) |
| acquisition | ✅ | 相机/传感接入 |
| end_effector | 可缺省 | 末端执行器声明（有末端即声明；无末端省略 = 引擎不注册抓取能力，诚实语义） |
| diff_drive | 可缺省 | 差速底盘域声明（有差速底盘即声明；省略 = 引擎不注册按名导航，诚实语义） |
| words / policies / fastbrains / output / safety / reactions | 可缺省 | 对应能力空白 = 诚实缺省 |

校验总原则:**未列字段即拒收**(deny_unknown_fields)——拼写错误/缺失必填 = 解析期拒;校验器输出分段问题清单,清单非空 = 拒绝装载。

## 2.5 传感与数据面声明(观测各块的物理来源——逐块对齐)

| 观测块 | 传感来源 | 包内声明 |
|---|---|---|
| q / dq / tau | 关节状态快照(编码器/力矩) | `[protocol.dds.sensor_topics.joint_state]`(如宇树 rt/lowstate) |
| imu(10) | 本体 IMU(多数随关节状态快照内含,如 G1 lowstate) | 随 joint_state 快照——无需独立 topic |
| contact(6k) | **接触力传感**(如腕部六维力×2) | **数据面声明**:路数 k(≤8)+ 每路传感位置(路序包文档化) |
| 相机帧 | RGB/深度相机 | `[acquisition.cameras]` |
| 音频(STT/TTS) | 麦克风/扬声器 | acquisition 扩展段 |

数据面规则:

- **k 必须与数据面声明一致**——obs_contact 行的 contact 块路数来自数据面声明,不是行里随意填的数。
- **无传感 = 对应行不可声明**——没装腕部六维力就不许交付 obs_contact 行(诚实缺帧语义会立即收场,上机必挂)。
- 只声明**现实存在**的传感(禁特权同源):仿真里方便但没有的物理传感,一律不得进数据面。
- 字段级声明格式(数据面段逐字段)随合作交付的完整规范提供;本公开版约束其规则与一致性。

## 3. 策略行(policies.rows)

| 字段 | 约束 |
|---|---|
| family | 枚举:balance / manipulation / deform / expression |
| name | 派发主键(认知按名派发),包内唯一 |
| weights | 包根相对路径,.onnx |
| frequency_hz | > 0(运行期下限钳 0.1) |
| priority | task / carry |
| obs_dim | > 0 且 ∈ 合法宽度集 |
| goal_conditioned | 缺省 false——true 时派发参数 goal_x/y/z/f 全有限否则 Err |
| obs_contact | 缺省 false——true 时观测追加 N 路接触力块(每路 6 维) |

**合法宽度集公式**:`{ b·J + 10 + 6k }(k∈[0,8])再按行声明 +4(goal)`——
J = joint_mapping.ordered 长度;b = 1 + motor_fields 中 :dq/:tau 字段数(未声明 = 3)。
G1 例:J=29, b=3 → 基础 97 / +goal 101 / +contact(k=2) 109。

观测契约(布局/单位/禁特权信息)见 `rl-training/contracts/obs_layout.md`。

## 4. 快脑行(fastbrains.rows)

| 字段 | 约束 |
|---|---|
| kind | ∈ {onnx} |
| weights | 输入 = 绑定策略 obs(逐位同源)+ 当前 goal(4);输出 = goal(4) |
| outputs.goal_stream | **交叉校验**:须对应包内存在且 goal_conditioned 的策略行 |
| rate_hz / budget_ms | > 0 / 回合预算硬帽 |

## 4.5 词行(words.rows)——认知调用的接口声明

词 = 认知层调用本体能力的**函数签名**——认知决策输出"词+参数",词绑定策略实例执行。

| 字段 | 约束 |
|---|---|
| name | 派发主键(认知按词名调用),包内唯一 |
| when_to_use | 认知选择依据(自然语言——何时该用这个词) |
| 操作绑定块 `[words.rows.manipulate]` | task.policy = 绑定的策略实例名(**包装载期交叉校验**:须存在且 family=manipulation);task/force = 语义标注 |

- word_schema_version 门(§1)保证词行 schema 与引擎匹配。
- 词开放:本体包按声明格式自定义词表,引擎不设固定词表。
- 例(样例包):`grasp_bottle` → 绑定 `reach_goal` 策略,task=grasp。

## 4.6 末端执行器段(end_effector)——抓取能力声明

> 声明制诚实语义：本体无末端 = 本段省略(合法)——引擎不注册抓取能力；
> 有末端即声明(机械可验收项实测填写，[样例] 项实测后调)。

| 声明件 | 管什么 | 规范 |
|---|---|---|
| `modality` + `params` | 碰哪里(接触几何) | jaw(对向双接触) / suction(单面吸附) / multifinger(收敛接触集——fingers=3/4/5 同模型参数化)；未知模态 = 装载期诚实拒绝(厂商专有经内建工厂扩展注册) |
| `actuator`(kind=joints) | 怎么收(运动翻译) | 闭合自由度 = 映射序内关节(open/closed_pos 须在该关节限位域内)；不在映射内的闭合(微码桥手)走厂商微码原语——kind 其他值拒载 |
| `close_tau_limit` 等三参数 | 收多紧、滑没滑(力控) | 声明即启用力模式：递进闭合→受阻停(抓握建立)→保持段滑移监视(SlipDetected)→重抓；缺省 = 位置式闭合(单发到 closed_pos) |
| `scorer_weights` | 哪组候选更好(学习版评分) | ONNX(契约 cand[n,17]→score[n,1]，RL 平台抓取成功数据集→训练→导出产物)；缺省 = 几何启发式评分(day-0 保底)；装载失败 = 拒载(回落 = 删声明，引擎不静默降级) |

字段规范权威 = `docs/body-package.schema.json`(end_effector / EndEffectorSpec / EndEffectorActuator)；
活样板 = `unitree-g1-complete`(双 multifinger 全家桶) / `noetix-bumi`(微码桥 jaw——闭合不在映射内的路线)。

## 4.7 导航域段(diff_drive)——按名导航的本体依据 + 空间工具面

> 声明制诚实语义：无底座或非差速形态 = 本段省略(合法)——引擎不注册按名导航，不静默降级；
> 有差速底盘即声明（几何参数实测填写——轮半径/轮距错 = 运动学解算错，必测项）。

| 声明件 | 管什么 | 规范 |
|---|---|---|
| `pose_channels` + `drive_channels` | 在哪/怎么走 | 底座位姿 [x,y,θ] + 驱动轮 [左,右] 通道名——**全部须在 joint_mapping.ordered 映射序内**(装载期交叉校验，越界 = 拒收)；位姿通道通常为被动伪关节(lowstate 位姿观测面，摩擦驱动非直驱) |
| `wheel_radius` / `wheelbase` | 运动学几何 | 轮半径/轮距(m)——正有限(校验域)；差速解算与轮速度匹配前馈(轮目标=q+(kd/kp)×dq，合力矩零防刹死)的输入 |
| `max_velocity` / `max_omega` | 速度域 | 线速度(m/s——导航减速带控制律输入 remain=tol+max_velocity×0.4) / 角速度(rad/s——原地转向对准上限)——正有限 |

执行链(引擎机制，包外零配置)：`device.motion.navigate {destination}`——按名检索 → 栅格 A*
规划 → 纯追踪差速 + 减速带到位控制律 → 到位回执；底座道仲裁 = 车道 2(全身认领压制主控输出)。

**空间工具面(device.spatial.*)——设备基础设施，不进包：**

| 工具 | 职责 |
|---|---|
| `device.spatial.map_set` | 栅格入账(bounds + obstacles 整体替换——与本体/场景几何一致；地名不受影响) |
| `device.spatial.place_put` | 地名入账(语义绑定："这是厨房"→名+位姿——部署/对话中入账) |
| `device.spatial.place_get` | 地名检索(未入账 = place_unknown 如实报错——导航按此解析目标) |

- **空间数据不进包**(数据主权)：栅格/地名长在端侧设备(`data_dir/spatial.sqlite3`，SQLCipher)，
  云端零空间数据；语义绑定 = 数据(非认知代码——机制层零场景词，扫描守卫机械锚)。
- 包只声明运动学依据(本段)；空间记忆与规划随引擎内置——任何形态本体都可入账地名，
  但按名导航执行仅在有 diff_drive 声明的本体可用(诚实语义)。

字段规范权威 = `docs/body-package.schema.json`(profile.diff_drive)；
活样板 = `fixtures/nav-base`(底座位姿 3 + 驱动轮 2，导航金任务全链验证)。

## 5. 动作语义(全体策略)

- 输出 = joint_mapping 序**绝对关节目标(rad)**,每拍整向量下发;引擎不做增量/保持/归一化。
- 出线钳入软限位 `[min+0.05, max−0.05]`;标定中立位必须在软限位内(装载校验)。
- 平滑性由训练约束保证(jerk 惩罚必选——rl-training 平台任务模板已内置)。

## 6. 签名口径

- ECDSA P-256,DER 签名写入文件顶层 `signature` 键(任何 [table] 之前)。
- 签名载荷 = **signature 赋值行置空为 ""** 后的完整文件字节(内容证明覆盖全文件)。
- 工具:`tools/sign_package.py`(占位→签→回填,三步);公钥 sec1 base64 交付灵智系统登记。

## 7. 校验清单(装载前,tools/validate.py 自动执行)

| 时机 | 校验 | 失败 |
|---|---|---|
| 包装载 | 必填段/版本门/family 枚举/obs_dim 合法宽度集/权重在场 | 拒收(问题清单) |
| 包装载 | 快脑 goal_stream 交叉校验 | 拒收 |
| 包装载 | 标定中立位 ∈ 软限位 | 拒收 |
| 包装载 | 末端交叉校验(重名/actuator 关节∈映射且目标在限位域/力参数域/scorer 权重在场) | 拒收 |
| 包装载 | 导航交叉校验(diff_drive 通道∈映射序/几何与速度参数正有限) | 拒收 |
| 派发 | goal 参数全有限 / estop 闩锁 | 拒派发 |
| 每拍 | obs.len==obs_dim;action.len==J | fail-fast |
| 每拍 | 软限位钳制 / 力联锁(声明时) | 钳制出线 / 立即收场+estop |
